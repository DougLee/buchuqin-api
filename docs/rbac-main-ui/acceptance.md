## 界面与实际修复

账号、角色、菜单、权限目录、权限审计统一了表格、表单、筛选栏、状态标签、授权卡片及弹窗间距。菜单/权限目录增加搜索，菜单编辑器改善布局，手机顶栏消除横向溢出。

浏览器验收发现并修复：
1. 平台操作权限集合直接 JSON 序列化成对象导致授权加载失败、侧栏空白；现在输出数组，增加真实 HTTP 契约测试。
2. 权限目录沿用旧权限码结构，空分组并误标作用域；现在共用菜单编辑器的登记接口目录，展示方法和路径，不推断数据范围。
3. 校区配置页存在快速切换选择时旧请求覆盖风险；增加请求顺序保护。跨校区读取权不能借用另一个校园写角色进行跨校区写入。

仅删除本地 checks 库 4 个明确的自建验收菜单：验收移动入口、验收外链、验收不缓存、验收缺失组件。删除前快照见 removed-test-menus.json。内置业务导航保留；“工作台”是无父节点的侧栏分组兜底。原验收脚本及历史证据保留。

## 验证结果

- API：40 套 / **287 项**测试全部通过；包含真实 PostgreSQL/HTTP 校区隔离、越权、撤权、会话失效、权限缓存、账号角色配置、商品订单库存采购等原有回归。
- 新增校区配置测试验证聚合读取、时段/公告 CRUD、伪造 body 校区、真实外校区 ID、客服电话默认值及无楼长提示持久化。
- 前端会话模块：15 个子场景，TAP 合计16项全部通过，含操作级平台范围及授权变化缓存失效。vue-tsc/Vite 构建通过；API tsc 与 Nest 构建通过。
- AdminController 清单146条路由全部分类。静态证据索引：101条直接HTTP调用，28条服务测试，17条源码复核；此数字不等于每个端点均做了每一种越权测试。权限目录145个去重登记模式，与路由数口径不同。
- 隔离升级库与此前空库引导完成的 migration 库均正常 deploy 新增3项迁移，现有 schema 与当前 Prisma 模型无差异。原历史迁移顺序问题仍按 docs/rbac/migration-guide.md 的 bootstrap 流程处理；本次没有伪称从零普通 deploy 可直接通过。
- checks/regression 为已有 schema 的隔离库，确认新增表/字段不存在后事务执行这3个SQL；不把它们计为完整迁移 ledger 演练。
