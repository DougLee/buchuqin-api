# 夜宵功能测试环境发布

API、管理后台和配送端均拉取 `feature/night-store` 最新提交。用户端本轮没有新增代码，沿用该分支现有版本。这里只说明发布顺序，不执行服务器操作。

## 数据库与服务

1. 在测试环境备份数据库，确认连接串指向测试环境。
2. 先发布 API，执行 `prisma migrate deploy`。现有 API Dockerfile 在启动时通过 `pnpm db:migrate` 自动执行；确认日志包含 `20261106100000_night_stock_workflow` 和 `20261106220000_night_product_management` 成功。后者为已有夜宵查看角色补充楼栋商品列表权限，并刷新权限版本。
3. API 健康检查通过后再发布管理后台、配送端，避免新版页面请求旧 API。

本次迁移不仅增加字段，还会回填历史库存货值、订单占用和已回库标记，关联夜宵商品与校区实物SKU，并扩展已有夜宵菜单权限。不能只执行 `prisma db push` 代替迁移。旧 `completed` 备货单保留历史已入库状态，不重新入库。

## 配送端测试构建

在配送端仓库运行（构建环境需安装项目依赖）：

```sh
VITE_API_BASE_URL=https://admin-test.buchuqin.com/api/v1 pnpm build:mp-weixin
```

微信开发者工具导入 `dist/build/mp-weixin-buchuqin`。必须显式指定测试 API，默认发布配置指向生产。

H5 若由测试域名同源代理 `/api/v1`：

```sh
VITE_API_BASE_URL=/api/v1 pnpm build:h5:buchuqin
```

输出 `dist/build/h5-buchuqin`，保持 `/h5/delivery/m/` 访问基路径和API同源反代。非同源部署则显式使用测试 API 完整地址，并配置相应 CORS。

本机5188/5192测试账号按钮只在开发模式展示，不作为服务器发布版登录方式。测试环境小程序仍通过已绑定楼长的微信账号登录；不要复制本机 `/tmp` 登录文件或 `.env.local` 到服务器。

## 发布后验收

- 后台「夜宵商品库」能从官方库导入，默认下架；编辑夜宵售价、上架后楼长备货页出现该商品。
- 后台先选择校区，再验证「夜宵商品库」的名称/条码、分类、上下架、仓库可用库存、官方导入/手工创建筛选。
- 「楼栋商品管理」按楼栋/楼长、商品/条码、分类、可售/冻结库存、校区许可、楼长上架筛选；配置商品不增加库存，校区停售/恢复许可生效，详情直接进入商品页。
- 「备货审核与出库」支持单号/商品/楼栋/楼长搜索、楼栋、状态及申请日期筛选；「盘点报损审核」另外支持申报类型。日期按北京时间自然日计算，列表显示符合条件的最近500条并分页。
- 配送端「进货备货」支持商品名称/条码搜索、分类切换及清空筛选；已选数量跨筛选保留，底部显示预占金额、备货进度入口和提交按钮。
- 商品仓库可用库存足够后，申请只预占额度；后台审核预留，出库后楼长确认实收才增加本店库存。
- 少收自动生成收货差异报损，审核通过后才释放差额。
- 盘亏/报损先冻结，驳回恢复；盘盈通过后才增加库存。重复收货、重复审核不会重复记账。
- 使用真实校区运营账号检查查看、审核与出库权限，以及跨校区访问拒绝。

本地自动化与浏览器验收结果、已有 RBAC 测试夹具失败和未覆盖的微信真机/退押异常边界，见 `IMPLEMENTATION_VALIDATION.md`。

## 本地模拟数据

`node scripts/preview-night-stock.mjs --skip-push` 在独立 `_spec` 数据库的 `night_stock_preview_20261106` schema 准备三栋楼、不同分类的带图商品、订单、备货各状态、冻结损耗和盘盈。实物库存通过申请→审核→出库→收货生成；模拟支付只在脚本中落本地账，无真实支付或推送。准备完成后以数据库标记跳过重复初始化，保留后续手工测试数据与管理员密码。可运行 `node scripts/test-night-preview-data.mjs` 检查余额、库存流水及重复执行。

此脚本用于本机3150/5191/5192联调，不向共享测试业务库或生产库写模拟数据；不要将本机登录材料部署到服务器。商品素材读取相邻用户端仓库 `../buchuqin-user-weapp/src/static/products` 并复制到本机忽略提交的 uploads 目录。
