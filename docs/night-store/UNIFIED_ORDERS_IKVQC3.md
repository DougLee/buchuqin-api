# IKVQC3 用户端统一“我的订单”

Issue：https://gitee.com/buchuqin-group/buchuqin-api/issues/IKVQC3

## 范围更正

用户明确：仅统一用户小程序“我的订单”中的白天单和夜宵单。配送端两类业务天然分开，后台也不在合并范围；上一轮误改的配送端、后台及相应API均已撤回。旧验收结果不代表本次更正后的功能验收。

## 方案

- 用户从白天或夜宵模式进入“我的订单”，默认同时看到本人两类订单，未完成订单跨日持续可见。
- 白天单/夜宵单标识，全部/白天/夜宵筛选；保留待支付、配送中、已完成、取消、退款、异常状态筛选。配送中包含夜宵待接单和已送达待确认。
- 所有读取仅绑定服务端登录用户ID，不以当前营业时段或当前店铺作为历史订单过滤条件。未完成优先、创建时间倒序、渠道+ID稳定排序后再分页。
- 单一来源失败显式提示列表不完整，可重试；换身份和晚到响应不串单，加载更多失败不推进页码。
- 原日/夜详情、支付、取消、确认收货与售后接口独立，库存和资金不合并。白天支付成功只处理白天购物车，夜宵支付只处理对应夜宵购物车。
- “我的订单”入口及计数统一；旧夜宵订单链接重定向统一页。优惠券和其他渠道业务仍保留原隔离。
- 未部署，不访问生产。当前工作在原 feature/night-store 分支。

### H5 交互验证

本地用户 H5 对接上述隔离 API，使用390px手机视口：

- 当前校区夜宵关闭，统一列表仍展示当天白天单、昨晚夜宵待接单和历史取消单；白天单、夜宵单均有独立标识。
- 夜宵筛选仅展示夜单；切回全部恢复两类订单。
- 点击夜单进入 `/pages/night/order-detail`，点击白天单进入 `/pages/orders/detail`，均成功加载各自详情。
- 旧 `/pages/night/orders` 链接重定向统一“我的订单”。
- 未付款取消的夜单显示“未支付”；已付款显示“实付”。
- 截图见 [user-orders.png](evidence/IKVQC3/user-orders.png)。商品图片为空系一次性测试夹具未配置图片。

支付分流、筛选竞态、身份变化、晚到响应、加载更多失败原页重试、单渠道故障、全局分页、跨用户隔离由自动化覆盖。微信真机支付、实际退款/配送不在本地H5验证范围，未连接微信网关。

### 修复与决定记录

- 保留历史订单读取，不依赖当前营业入口判定；“我的”页面渠道接口失败只影响相应优惠券，订单入口仍可用。
- API 最小列表 DTO 保留 `paidAt`，避免将未支付取消单误标为“实付”。
- 复用原渠道订单读取服务和支付/详情入口，不改渠道库存、资金与履约状态机。
- 全量回归发现既有多租户兼容测试缺少合法A校区楼栋，补齐测试夹具；没有放松产品地址校验。
- 两名只读评审指出的金额标识及入口依赖问题均已修复，并分别复核通过。
- 测试结束已移除临时登录入口及令牌文件、停止本轮 H5/API 服务；代码保留在现有 `feature/night-store` worktree，未提交、合并或部署。
