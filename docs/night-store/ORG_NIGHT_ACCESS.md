# 夜宵组织授权与校区开通

按2026-11-17确认的两个开关方案实现。只在原夜宵worktree开发，不发布生产。

## 使用方式

1. 超管在组织管理编辑组织，开启“夜宵经营授权”。新增组织默认关闭。
2. 本组织管理员在校区管理中为目标校区点击“开通”。同组织其他校区不跟随开通。
3. 已有夜宵菜单权限的账号可进入该校区夜宵配置，设置营业时段、商品和店铺。两个开关不扩大原有角色权限。
4. 已绑定店铺的正式楼长可以备货、开店。用户当前收货地址本楼店铺处于有效营业状态，首页才显示夜宵店。

校区尚未开通时，开通按钮在校区管理，不放在已隐藏的夜宵配置页。夜宵配置表单不再修改开通状态；旧客户端绕过表单提交同样不能自行开通。

## 开关与历史

- 新增`Organization.nightEnabled=false`，复用`Campus.nightEnabled`。两个开关均为true且组织在用时，服务端才允许新增夜宵经营。无组织归属、缺失配置、停用组织均不放行。
- 组织授权变更会将其下属校区夜宵开关关闭，并关闭营业中/暂停中的夜宵店；需要组织管理员逐校区开通和楼长主动开店。单独修改组织档案不改变开通状态。组织停用、校区转组织同样不会自动恢复夜宵营业。
- 关闭校区停止新增经营，不清除订单、押金、库存或流水。历史订单、收货、退款、报损审核和结算按原权限收尾。
- 从未使用夜宵且没有历史义务的组织/校区不显示夜宵菜单、设置、营销渠道或订单筛选。存在真实历史的保留收尾入口；单纯空店、空商品配置不视为库存义务。
- 用户订单仍按本人汇总白天和夜宵。只有本人存在夜宵订单时显示渠道筛选；关闭后旧订单不会消失。

## 服务端约束

- 超管维护组织授权；校区开通仅允许超管或本组织管理员通过原校区管理接口修改，组织边界继续沿用RBAC。
- 夜宵路由统一校验有效开通或有限的历史操作；用户下单、楼长备货/押金/营业入口使用统一判断。
- 普通优惠券、Banner、促销、公告接口中的夜宵参数和已有夜宵记录也检查开通，不能用共享接口绕过。
- 后台权限响应按当前所选校区裁剪夜宵菜单；切校区/换号时清理旧可见状态。后台公共营销页面和用户订单页同步隐藏无关选项。
- 保留营销`capabilities=null`的旧兼容语义，不将组织夜宵授权混入该字段。

## 发布与验证

新增迁移`20261117160000_organization_night_access`只添加组织布尔列，默认false，不自动授权现有组织，不修改白天业务数据或既有营销白名单。发布后应明确选择试点组织及校区，不能通过演示seed自动开通。

### 2026-11-17 集中验证结果

所有数据库验证使用本机 `127.0.0.1:15449/night_parity_spec` 下的新建独立 schema `night_stock_parity_fullorgaccess20261117`。API 预加载 HTTP 出站隔离，未连接生产 API、生产数据库、微信支付或存储网关。

- API：完成一次全量回归（86 个套件、744 条用例）。4 条失败源于测试缓存隔离及旧的“关闭后仍展示店铺”预期，修正后只复测受影响的 2 个套件，76 条全部通过；其余 84 个套件已通过。HTTP 端到端另 5 条全部通过。
- 后台：30 条脚本测试通过，类型检查及生产构建通过。
- 用户小程序：全量脚本测试、类型检查、H5 和微信小程序构建通过。
- 配送小程序：全量 30 条脚本测试完成；其中历史页面的旧测试补充真实历史前提后，受影响的 15 条定向复测全部通过。类型检查、H5 和微信小程序构建通过。
- 迁移验证：临时旧形态组织表执行新增列 SQL 后，存量行默认未授权，既有营销白名单（含 null）保持原值。

本地真实接口/H5 验收使用额外独立组织、校区、正式楼长及用户，覆盖：

1. 组织未授权：后台无夜宵菜单、校区列表无夜宵服务列，旧校区开关即使为 true 也不生效。
2. 超管授权组织：旧校区开关被关闭，组织管理员能看到“开通”按钮，夜宵配置尚不显示。
3. 组织管理员通过页面开通校区：夜宵配置/菜单及楼长切换入口出现；空店未营业时用户首页仍为白天。
4. 通过真实备货审核、发货、收货补充库存（押金使用本机模拟到账，不调用支付网关）；楼长 H5 开始营业后，本楼用户首页出现夜宵商品。
5. 无本人夜宵历史时用户订单页不显示渠道筛选；创建本人夜宵订单后，合并列表显示夜宵标识。
6. 组织管理员通过页面关闭校区：新夜宵订单返回 403，夜宵配置和楼长切换入口隐藏，用户首页恢复白天。既有用户夜宵订单仍可见，楼长“我的”保留夜宵历史与待办。

决策记录：沿用现有菜单授权，不自动给任何角色增加夜宵菜单；组织授权变更清除校区开通状态，避免重新授权时旧店自动营业；空店/零库存商品不构成历史义务。

当前修改只在四个 `feature/night-store` worktree 中，未发布测试或生产。部署需先应用上述迁移，再由超管授权试点组织、组织管理员开通试点校区；新授权不替代原有菜单权限配置。真实微信收信仍是[140的独立待验项](WECHAT_MESSAGE_RECEIPT_140.md)，本次授权验收不替代真机消息验收。
