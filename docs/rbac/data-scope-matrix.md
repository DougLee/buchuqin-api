## AdminController 以外的边界

- `/files/images`：JwtAuthGuard 后仍需要后台账号实时校验，详见上表。不能仅依赖 JWT 有效期。
- `/auth/admin/campuses?purpose=filter`：仅返回本人可用的校区名称；平台允许全部，固定校区授权不扩大；不返回校区管理配置/计数，不改变默认可切换列表。
- `/auth` 后台登录、修改密码、切换校区、可选校区：AuthController 与 RBAC 会话检查，由 auth/admin-campus-access/rbac.integration 测试覆盖；不是公开的业务数据接口。
- 小程序/员工接口保留其独立身份鉴权。本次不能把后台权限直接套给客户或履约员工；若共用上传入口，分别校验身份。
- 前端导出基于已返回行，不存在额外的全量导出权限绕过接口；房间模板及导入为独立 REST 路由，已纳入清单。

## 前端动作

DataPage 的创建入口使用实际 POST 权限；编辑、删除、确认、支付、打印、寝室导入等分别使用对应 HTTP 权限。页面级 canWrite 仅作为操作区容器判断，不能代替单个按钮授权。hasPerm 使用与后端一致的方法、单段参数及尾斜杠匹配。后端仍是最终权威，浏览器隐藏不是安全边界。

范围验收由表中实际测试与源码复核共同支撑；矩阵本身不是运行证据。

## 既有价格字段的分类边界

当前商品列表沿用主线 `AdminService.products` 输出 costPrice/wholesalePrice；源码明确 costPrice 由前端控制显示，不能把前端隐藏宣称为后端字段保密。扫码回填则已有 costPrice 剔除。官方库与分类是共享资源，校园商品记录仍按校区限制。此前修复的批次 purchaseReceivedTotal/grossEstimate 属于跨校区采购财务汇总，与本校商品行自身价格字段不是同一类信息。

已核对固定主线的产品输出与订单毛利实现：保留既有记录内成本口径，本目标要求的独立改价权限不等同新增独立成本读取权限。操作指南已明确此边界，不宣称前端隐藏能够保密。

本轮新增有效目标测试：rbac-scope.integration 的列表循环覆盖 Banner、优惠券、库位、提成、打印机和促销（静态索引可能不识别循环变量）；另覆盖售后、库存流水、新订单水位线、配送配置、楼栋写入、转盘外校券、业务审计、商品/招募计数、招募转面试、优惠券/库位创建及打印机绑定。外部打印服务使用 mock，无云端写入。

业务审计测试发现 RBAC 授权快照跨校区信息泄漏，已修复：普通 auditLogs 查询排除 rbac.*，只由独立平台权限审计端点提供授权记录。真实 A/B 绑定构造了修复前失败、修复后通过的反例。
